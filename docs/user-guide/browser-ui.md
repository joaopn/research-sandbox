# The browser UI

`research webui start` serves a single-page app over HTTPS, by default at `https://localhost:7777`. With the **broker** running it's a full control plane; with it stopped it's a read-only terminal surface. It's the recommended way to drive everything short of authoring images.

The left rail lists your projects, with four entries at its bottom (five when Search is switched on to show there):

| Page | Opens as | What it does |
|---|---|---|
| Projects rail | Always shown | Lists projects and opens their tabs; host CPU and memory at the bottom (click them to open Host) |
| New Project | Floating window | Workflow cards to create a project; import an existing one |
| Search (when switched on) | Tabs: Quick Search, Activity, Settings | Services → Search as a page of its own, directly above Services |
| Services | Tabs: Gitea, Repos, Fetch, Reviews, MCP, Aldine, Search | The dev lane: the shared Gitea and its backups, repositories and their image builds, fetch commands, reviews; MCP servers; the shared Aldine LaTeX editor; the shared search service (Quick Search, Activity, Settings) |
| Host | Tabs: Projects, Software, Ports, Defaults | The project table; agent, editor and image builds; pass-through ports; the default models of a new researcher-subagents project's referee, analyst and surveyor, and the task limit per project |
| Settings | Floating window | Interface settings kept in the browser: themes, layout, zoom, terminal font |

- **New Project.** A grid of workflow cards grouped as Research, Base and Store (see [Workflows](workflows.md)). Click one → a prefilled create form → **Create** → live progress as the project comes up. Claude's tab in the form's Agents box has **Block links to the Anthropic account**, on by default: Claude in the project gets no claude.ai connectors, no Remote Control, no Claude in Chrome and no claude.ai artifacts. Switch it off to allow all four. Each card's **Explain** opens its learning material (or the repo's README, for store cards). **Import project** adds a box you run elsewhere, by its SSH address; a project on this host is added with Attach under Host → Projects.
- **Services.** The **Gitea** tab shows the shared Gitea, with a bar on top to turn it on, upgrade it, set its admin password and, with **Backup**, take or discard a backup of the whole Gitea. **Repos**, **Fetch** and **Reviews** cover the rest of the dev lane: repositories, with each one's built image and its Build, Cancel and Discard buttons; fetch commands; pull request reviews (the reviewer's default model is at the top of Reviews). **MCP** holds the MCP servers behind the shared gateway and which agents may use them (see [Capabilities](capabilities.md)); **Aldine** shows the shared LaTeX editor itself, with a bar on top to turn it on, update it, open it in a new browser tab and turn it off; while it is off or stopped, a line under the bar says so. **Search** has three sub-tabs, and opens on the one last used in this browser (on Settings while the service is not running). **Quick Search** asks the searcher a question yourself, in a chat with its own list of conversations: each message is a new, independent search with the agents' searcher, waiting in the same queue as theirs, and its answer shows the summary with numbered sources, a fold-out of what it did, **Copy** and **Report**; while it runs, its time, tokens, last tool calls and **Stop**. The tick **include this conversation's earlier questions and answers** (off by default) sends the whole conversation so far with the new question, which costs more tokens with every message and is refused past 32,000 characters. Conversations are kept on the search service's disk until you delete them or clear them: each has its own delete button in the list, **Clear conversations** (beside **New conversation** at the top) removes them all, and the list is resized by dragging its edge. **Activity** lists the waiting and running searches: who asked ("operator" for your own), the question, the searcher, the state, a running time and the tokens used so far (input, output and cache tokens), read when the tab opens and every few seconds while it is open. Click a row to see the last few things the search did, each tool call with its tier, read-only and as plain text (it carries text from the pages the search read); **Stop** ends a search, and the agent that asked is told the operator stopped it. Under it, **Recent searches** lists the searches that ended, newest first, with how each ended, when, how long it ran and its tokens: the last 20 by default, set by **recent searches kept** in the searcher's settings (at most 100; 0 turns the list off). It is kept in the search service's memory only, so a restart of the service clears it. Click a recent row to see the search's question and last work as it ended, also after it was collected, until it drops off the list or the service restarts; its files are not kept. A recent row whose search wrote a report has a **Report** button that shows its summary, sources and what it tried (with a **Copy** button for the whole report as text), kept in full in the search service's memory while the row is listed. **Settings** has the service's bar (turn it on, update it, turn it off, clear the ended searches nobody collected), its sign-in with **Test** (one tiny model call that checks the stored sign-in; it costs a fraction of a cent), its searcher's settings (see [Capabilities](capabilities.md)) with the two browser tiers' switches, **Browser** (a headless Chromium, for pages that need rendering or refuse a plain fetch) and **Stealth browser** (camoufox, a browser that looks like a person's, for pages that block the browser), both on by default and tried in that order after the plain tier (each running search gets its own browsers, which cost memory while it runs, and their images add about 4.8 GB at Turn on; see [the browser tiers](../architecture/Search.md#the-browser-tiers)), and **Show Search in the sidebar**, which adds Search to the sidebar above Services with the same three tabs; it is kept on the host, so every browser shows the same. See [Search service](../architecture/Search.md#quick-ask). While Gitea is not running, Repos and Fetch are hidden, and Reviews says Gitea is off while still showing its history.
- **Host.** The **Projects** tab lists the host's projects in a sortable table — workflow, state, SSH address, and disk size on request. **Attach** puts a running project back in the sidebar; a project the sidebar cannot show — its container gone (orphaned) or stuck in another state than running or stopped — has **Destroy** there. Start and stop are on each project's sidebar row; update and destroy in its ⚙ → Project. **Software** holds the agent and editor downloads, the image fleet, the version pins, and the apps RS's own project and box types install (OpenKnowledge: check npm for a newer release and move every OpenKnowledge project and box to it at its next start); **Ports** the pass-through ports; **Defaults** the models a new researcher-subagents project starts with for its referee, analyst and surveyor, and the task limit of each project container. Clicking the CPU and memory bars above the sidebar buttons opens Host too.
- **Tabs remembered.** Services and Host each reopen on the tab you used last.
- **The projects rail.** Running projects sit in the order and groups you drag them into; each row has Stop and ⚙. Stopped ones sit in a "Stopped (n)" fold below, each with Start and ⚙. Stop and Start ask inside the row first; the row moving is the feedback.
- **Per-project settings (the ⚙ window).** The gear on a project's row opens a floating window with these sections:

  | Section | What you set |
  |---|---|
  | Tabs | Which of the project's tabs show |
  | Extensions | The editor and the Reader on or off; the agents' status bar |
  | Agents | Which agents the project carries, their models, Update (deploys the downloaded agent versions live); a box's agent model; whether Claude's links to the Anthropic account are blocked, for the project and for each Claude box (Claude sessions started afterwards follow a change) |
  | Sharing | The project's read-only folders (applied at its next start) and each box's folders (saving restarts that box fresh, which signs its agent out) |
  | Ports | Ports a project or box serves, as tabs |
  | Alerts | Arm a notification when one of the project's agent sessions hands back |
  | Project | Update (running projects: recreates the container with the latest templates), Destroy (type the project name *and* the master password again; a stopped project has only this), Remove from sidebar (drops this browser's bookmark) |

- **Boxes.** On a project with inner Docker, the **+** button on its tab strip adds a box (a type plus agent / editor / MCP options); the ✕ on the box's terminal tab removes it. See [Capabilities](capabilities.md#boxes).
- **Terminals + editor.** In-browser ssh/byobu terminals per service (xterm + host-key TOFU + Ctrl-F search) and the code-server editor in an iframe; drag tabs to arrange up to three columns side by side. Each editor and app gets its own origin port, so each keeps its own browser storage.
- **Activity and alerts.** Each project row shows small coloured boxes counting the interactive Claude Code and pi sessions in the project and its boxes: green working, amber waiting for you, blue subagents running. Hovering a box says where each number comes from. A Claude session opened in the editor counts too: closing its tab ends it, but hiding the editor's right-hand side bar leaves its Claude view running until the editor is switched off or the project stops. A new project's editor starts with that side bar closed, so Claude starts only when you open it. A project armed under ⚙ → Alerts shows a bell; when one of its sessions hands back, the page shows a corner notice, marks the tab title while the tab is in the background, and sends a browser notification where the browser allows it.
- **Sign-in.** One **master password** covers the browser. You choose it when the browser's vault is first created, and it must match the password set on the host with `broker passwd`. The browser derives two values from it: one encrypts your saved project bookmarks and interface settings *in the browser* and never leaves it; the other signs in to the broker. Neither the webui nor the broker receives the password. Unlocking signs in for eight hours; locking signs out. Signing in to an **agent** is still per-project, inside it (`claude` then `/login`, or `pi` then `/login` with an API key).

> [!NOTE]
> This is the **single-operator** setup — one master password, proportionate for a localhost / private-tailnet box. The webui and broker run as **you** (same uid): that's the contract that lets the webui reach the broker's socket, and the webui holds **no docker socket** of its own. Ten failed sign-ins within a minute block sign-in for a minute, but there are no per-user accounts and a destroy cannot be undone: keep it off networks you do not trust.

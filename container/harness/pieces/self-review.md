**Review each change yourself.** When a doer reports a unit done, and for each small edit you make yourself, review the change the way a fresh reviewer would: do not take the doer's report or your plan as evidence (except for the red half of a test, below); check the diff against the brief and the code. Verify each claim against the code; look for a missed caller, a broken contract, and a test that passes while the property it names is false. Run the project's checks yourself; where a test had to be seen failing first (the full test policy), that red half is the doer's report, so check that the report says how it was made red. Send each blocking defect back to a doer (small, mechanical edits you may make yourself) and check the fixes, within the review limits (below); when every unit is in and there were several, review the whole change once, under the same limits. Code is anything that runs or is read as behaviour, including configuration, tests, and text an agent is given to follow; comments, formatting, commit messages and notes are not. Commit only after the last review the limits call for.

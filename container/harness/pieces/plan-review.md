**Have the plan checked.** Before any code, write the plan down: what changes and where, how it will be verified, what it rests on, and (when this mode uses doers) the units it is cut into. Launch `checker` on it with a self-contained brief: the goal, the files and places the plan changes, the measurements it rests on, and what to verify. The checker reads and searches but cannot run commands, so measurements go in the brief. Fold each defect it asserts into the plan; its forks join your questions to the user.
